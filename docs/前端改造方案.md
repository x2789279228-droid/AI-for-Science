# Meridian 前端改造方案 v1.0

> 目标读者：实施者（你自己）+ 答辩材料撰写者。
> 基线：`main @ 4ad8d75` + 工作区未提交的 RISO 改版（约 1300 行）。
> 一句话纲领：**克制的外壳、被打穿的细节、内容即视觉**——把证据、图谱、译文从"小卡片"里放出来当主角。

---

## 0. 方案总览

### 0.0 基线实测（2026-11-11，先于一切改动）

- **构建状态**：未提交改版 `next build` 通过（真实 exit 0，12/12 静态页生成；此前一次 exit 1 为 PowerShell 管道伪报）。P0 阶段不需要先修构建。
- **遗留告警**：`BrandIntro.tsx:134` 一条 `react-hooks/exhaustive-deps` Warning（`risoMode` 未入依赖数组）——C1 提交时顺手修复。
- **包体积**：`/graph` First Load JS **559 kB**（G6 411 kB 未按需加载）；其余页面 95–190 kB。可选项：图谱页 G6 改 `next/dynamic` 懒加载（与 echarts-gl 现有模式一致），P5 阶段评估是否纳入。

### 0.1 要解决的三个诊断结论（来自真实运行截图审计）

| # | 诊断 | 证据 |
|---|---|---|
| D1 | 视觉主角被关在小容器里 | 图谱 G6 画布仅 ~480px 高且节点标签截断（`BERT: Pre-trai`）；Chat 空状态是空旷页面中一张小卡片 |
| D2 | 第一屏没有叙事 | 首页 = 上传卡片 + 文件列表，像文件管理器；系统已有资产（22 篇论文 / 991 refs / 2371 引用边 / ClaimTrace）不可见 |
| D3 | 品牌层半成品 | RISO 皮肤只刷了卡片层（侧边栏选中态、图谱、ECharts 未跟进）；halftone 网点压字；`评审模式 D11` 徽章暴露未完成 |

### 0.2 设计决策（本方案的"宪法"，后续所有页面服从）

| 决策 | 结论 | 理由 |
|---|---|---|
| **皮肤策略** | 经典浅蓝 = 唯一工作皮肤；RISO 从全皮肤降级为**品牌层**（intro 动画、印章语义、答辩材料、功能索引树） | UI/UX 仅占评分 10%，不全押审美偏好；半套 RISO 必须消除；印章语义（证/基）是功能而非装饰 |
| **惊艳来源** | 不做任何装饰性元素；惊艳 = 证据链的三次"演出时刻"（E#→PDF bbox / 引用星图 / 双语同步线） | 学术产品的信任来自克制，记忆点来自内容 |
| **主题切换器** | 从侧边栏下线 RISO 切换按钮（代码保留，CSS 变量保留，`?theme=riso` 可强制用于截图） | 消除"半成品皮肤"的日常暴露，同时保住答辩截图能力 |
| **信息架构** | 9 个导航项不变；首页从"文献库列表"改为"研究工作台"（文献库列表仍在，降级为首页一个分区） | 评委第一屏必须 3 秒看懂系统 |
| **排期徽章** | 全部移除（D11 及一切 `schedule` 字段）；`/judge` 改为"评审导览"页 | 未完成信号是扣分项 |

### 0.3 成功标准（验收时逐条核对）

1. **3 秒测试**：首次看到首页的人能说出"这是一个给论文回答找证据的系统"。
2. **图谱舞台**：22 篇论文全量下图布高度 ≥ 600px，节点标签零截断，社区有凸包底色。
3. **Chat 路径**：从空状态到发出第一个演示问题 ≤ 2 次点击；空状态不再是"说明书"而是"入口"。
4. **工程**：`pnpm build` 绿、e2e 全量绿（10 旧 + 新增）、控制台零新增报错、所有改动进入一次或多次提交且 CI 绿。
5. **一致性**：任意页面截图中不再出现"浅蓝胶囊 + RISO 硬边"混排；不再出现任何排期徽章。

## 1. 设计系统层（tokens / 字体 / 语义色）

涉及文件：`web/app/tokens.css`、`docs/design-tokens.md`、`web/app/globals.css`、`web/public/fonts/`。

### 1.1 字体系统（已具备资产，只需规范使用）

现有自托管字体（`web/public/fonts/`，已子集化）：

| 字体 | 角色 | 使用规则 |
|---|---|---|
| Noto Serif SC | **中文展示体** | 页面主标题（h1）、品牌词、印章字；正文禁用 |
| Playfair Display | **西文展示体** | 品牌词 MERIDIAN、大图数字；正文禁用 |
| 系统 sans 栈 | **正文/控件** | 一切正文、按钮、表格、标签 |
| JetBrains Mono | **数据/代码/路径** | E# 编号、页码、耗时、token 数、路径 chip |

行动：
- 在 `tokens.css` 定义 `--font-display-cn` / `--font-display-en` / `--font-data` 三个语义变量（现状是散用），全部页面收敛引用。
- `layout.tsx` 中 `<link rel="preload">` 只预载 NotoSerifSC 子集（首屏标题需要），其余按需。
- h1 字号统一 `--text-h1: 26px`（展示体 serif 视觉大，26px serif ≈ 30px sans 的量感），禁止再出现 20/22/24 混用。

### 1.2 印章语义系统（RISO 降级后的核心保留资产）

新增 tokens：

```css
--stamp-verified: var(--riso-klein-deep);   /* "证"章：claim 已验证 / 证据齐全 */
--stamp-cornerstone: var(--riso-orange-deep); /* "基"章：图谱基石论文 */
--stamp-bg: var(--riso-paper);               /* 章底色（米白纸） */
--stamp-border-style: 1.5px solid;           /* 硬边、微旋转 -2deg */
```

组件：新增 `web/components/Stamp.tsx`（约 40 行）：

- 两种 kind：`verified`（证）/ `cornerstone`（基）；
- 三种 size：`xs`（行内 16px，用于 claim 行首）/ `sm`（22px，节点徽章）/ `md`（36px，仅答辩材料）；
- 出场动效：scale 1.4→1 + rotate -6deg→-2deg，spring 260ms，`prefers-reduced-motion` 时直接静止呈现；
- 行内印章默认 `opacity: .9`，hover 时显示 tooltip（"该论断已通过 L1–L4 校验" / "PageRank 前 20% 且出度≥3"）。

**使用红线**：印章只允许这两种语义，禁止用作"新功能""热门"等营销标记；同屏印章 ≤ 12 个（超过则只标前 N 个 + "等 N 项已验证"汇总）。

### 1.3 语义色收敛

- 现状 `--ok/--warn/--danger` 已规范，保持；
- ClaimTrace 三态 + absent 第四态的颜色在 `globals.css` 收敛为四个 token：`--claim-ok / --claim-check / --claim-bad / --claim-absent`（absent 用中性灰蓝，区别于 unsupported 红）；
- RISO 全部 primitive 变量保留在 tokens.css 底部并注释"品牌层专用，工作皮肤不引用"，避免误删（`?theme=riso` 截图仍需要）。

### 1.4 动效预算（全局宪法级约束）

| 场景 | 时长上限 | 缓动 |
|---|---:|---|
| hover/焦点态 | 120ms | ease-out |
| 卡片/列表入场 stagger | 单项 240ms，间隔 40ms，一组 ≤ 8 项 | cubic-bezier(.22,1,.36,1) |
| 抽屉/弹层 | 280ms | 同上 |
| 印章落章 | 260ms | spring |
| Trace 节点点亮 | 现状保留 | 现状保留 |
| BrandIntro 全片 | 现状保留（约 2.5s，每会话一次） | 现状保留 |

- 全局 `prefers-reduced-motion: reduce` 媒体查询下：所有入场/ stagger / 印章动效关闭（BrandIntro 已遵守，新增代码同口径）。
- 新增动效一律使用 WAAPI 或 framer-motion（已在依赖内），**禁止新增动画库**。

### 3.3 WorkbenchPulse（双卡：最近问答 + 图谱速览）

- 数据源：`qa_logs` 已有表 → 需后端给一个轻量 `GET /api/qa/recent?limit=3`（id/question/时间/claims 统计：supported/check/unsupported 计数）。实施时确认是否已有等价接口（`lib/api.ts` 有 `fetchQaTrace`，无列表接口）——**这是本方案唯一的后端新增点**，约 30 行路由 + 测试；
- 无数据时：显示"还没有问答——去 Chat 提第一个问题" + 跳转按钮（空态规范见 §7.9）；
- 每条：问题 1 行截断 + 三态计数迷你徽章 + 时间；点击跳 `/chat?thread=`（若无 thread 恢复入口则跳 `/chat`）。

**右卡·引用图谱速览**：
- 用 G6 渲染**只读缩略图**（关闭交互、隐藏标签、动画关闭），节点 22/边 50 规模无性能问题；
- 点击整卡跳 `/graph`；
- 角落放 mono 角标：`22 节点 · 50 边 · Q=0.2434`；
- 加载中显示骨架屏（灰色脉冲块），失败显示静态插画（Illustrations 里取）+ "图谱暂不可用"。

### 3.4 文献库分区（现有逻辑迁移）

- 现有上传卡片、去重预警卡、版本族书堆、论文列表**整体下移**为首页第三个分区，逻辑零改动；

- 首页滚动：页面整体自然滚动，不做内部滚动容器。

### 3.5 首页加载策略

- 三个分区独立加载、独立骨架：数据带（papers+health 已到即用）→ Pulse 双卡（并行两个 fetch）→ 文献列表（现有逻辑）；

- 所有 fetch 失败静默降级为空态插画，不弹错误横幅（首页不是操作台）。

## 4. 页面改造 · Chat（/chat）：空状态即演示入口

涉及文件：`web/app/chat/page.tsx`、`web/components/chat/TracePanel.tsx`（仅样式微调）。

### 4.1 空状态重写（最高优先）

现状：居中小卡片 + 文字说明。改为**演示问题卡组**：

```
        ✦ 向文献提问 —— 每个论断都带证据
   ┌─────────────┐ ┌────────────┬─────────────┐
   │ 模型用了多少块 │ │ BLEU 分数是 │ │ 对比这篇论文的 │
   │ GPU？        │ │ 多少？      │ │ 预训练目标     │
   └─────────────┘ └────────────┴─────────────┘
```

- 问题卡内容**按当前选中论文动态选择**：
  - 若选中论文是 Attention Is All You Need → 用上述三题；

- 空状态下右侧 Trace 面板显示"等待首次提问 · 提问后这里逐步点亮"（一句话，不是段落）。

### 4.2 回答区证据语义增强

- ClaimTrace 行首接入 **Stamp verified（xs）**：当 claim 状态为 supported 时显示（现状是三态文字徽章，印章与徽章并存：徽章表状态、印章表"已验证"的仪式感）；

- 回答正文行宽限 68ch、字号 15px（阅读舒适度），现状偏小则上调。

### 4.3 输入 dock

- 现状保留（检索范围/路由/Agent chips/发送按钮），仅把"生成式·引用已后验"等状态 chip 对齐到右侧一行；

### 4.4 Trace 面板

## 5. 页面改造 · 图谱（/graph）：放出笼子（核心工程项）

涉及文件：`web/app/graph/page.tsx`（画布初始化、数据处理）、`web/app/globals.css`。

### 5.1 舞台化布局

- 画布容器从固定 480px → `height: calc(100vh - var(--topbar-h) - 180px)`（约 620–660px @900px 视口），最小 560px；
- 工具栏从两行压成一行：统计 chips（22节点/50边/Q值/基石/边缘）收进一个"图谱信息"下拉，主行只留：选择论文、沉浸全屏、导出 PNG/JSON、社区选择、生成综述/社区综述、研究缝隙、外部核查；
- 图谱信息下拉：点击"ⓘ 图谱信息"展开 popover 显示全部统计（现有 chips 移入）。

### 5.2 节点标签零截断

现状：G6 label 按字符截断。改为**关键词提取**：

```ts
function nodeLabel(title: string): string {
  const t = title.replace(/\n/g, " ").trim();
  // 1. 冒号前是短大写词 → 用作标签（BERT: Pre-training... → BERT）
  const pre = t.split(":")[0].trim();
  if (/^[A-Z][A-Za-z0-9\-+]{1,14}$/.test(pre) && pre === pre.toUpperCase().replace(/[^A-Z]/g, c=>c) ) return pre;
  if (/^[A-Z0-9][A-Z0-9\-+ ]{1,15}$/i.test(pre) && pre.length <= 15 && t.includes(":")) return pre;
  // 2. 含已知缩写词典命中 → 用缩写（LoRA / GPT-3 / ViT / T5 / XLNet...）
  const ABBR = ["LoRA","GPT-3","GPT-2","ViT","T5","XLNet","BERT","RoBERTa","DeBERTa","ALBERT","ELECTRA","BART","Longformer","Big Bird","Reformer","FlashAttention","Megatron-LM","Scaling Laws"];
  for (const a of ABBR) if (t.toLowerCase().includes(a.toLowerCase())) return a;
  // 3. 回退：前 3 个词 + 省略号样式由 G6 自身处理
  return t.split(" ").slice(0, 3).join(" ");
}
```

- 词典放文件顶部常量，标注"可按语料扩充"；中文标题直接走回退（前 3 词对中文无意义，中文返回前 10 字）；
- label 样式：sans 11px、深色 80% 透明底白 2px padding 保证压线可读。

### 5.3 社区凸包底色

- 使用 G6 v5 内置 `Hull` 插件（`@antv/g6` 5.1.1 已含）：按 Louvain community id 分组，每社区一个 hull，`fill` 用社区色 8% 透明度，`stroke` 无；
- 数据就绪后 `graph.addPlugins([new Hull({ members: ... })])`；节点拖拽时 hull 自动更新；
- **降级路径**：若 Hull 在该版本 API 有出入，回退方案为节点 3px 社区色描边环（已实现成本低），并在 checklist 如实记录"hull 未启用"；
- 验收：22 篇全量下，≥2 个社区有明显可分辨的底色团块。

### 5.4 基石/边缘印章

- 基石节点右上角叠加 Stamp `cornerstone`（sm，22px，米白底橙边"基"）；
- 边缘衍生节点不盖章（避免满屏章）；改为节点色环保持现状；
- 图例区（画布左下角，半透明底）：
  `● 大小=PageRank   ◐ 颜色=社区   证=已验证   基=基石论文   — 边粗=含金量`

### 5.5 节点详情抽屉

- 点击节点 → 右侧 320px 抽屉滑入（280ms）：论文标题、角色徽章+role_reason、PageRank/出入度/介数、引用句样例（edges[].examples 已有）、按钮组（去阅读 / 去问答 / 加入对比）；
- 再次点击画布空白或 Esc 关闭；抽屉打开时画布不位移（覆盖式）；
- 现状"点击节点跳详情"的行为若存在则替换为抽屉。

### 5.6 性能验收

- 22 节点/50 边 + hull + 标签：首帧 < 1.5s，拖拽/缩放 55fps+；
- 沉浸全屏切换：重建画布（现有 epoch 机制）< 1s；
- e2e ⑤ 现有"20 篇 ≤60s"断言保持通过（布局变化不破坏测试选择器，注意保留 `data-testid` 或 canvas 容器类名）。
