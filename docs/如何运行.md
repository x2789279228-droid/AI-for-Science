# 如何运行本项目（Runbook）

> Meridian 科研助手 Agent：PDF 深度解析 · 抗幻觉溯源问答 · 中英联动阅读 · 检索推荐 · 图谱综述 · 写作 Copilot。
> 后端 **FastAPI**（`api/`）+ 前端 **Next.js**（`web/`），单机 SQLite，无需重型基建即可本地起全栈。

---

## 0. 环境要求

| 依赖 | 版本 | 用途 | 缺了会怎样 |
|---|---|---|---|
| **uv** | ≥0.11 | Python 依赖安装与运行 | 后端无法启动；`pip install uv` |
| **Python** | ≥3.11 | 后端运行时 | uv 自动拉起，无需手动装 |
| **Node.js** | ≥18 | 前端构建 / 类型检查 | 前端无法启动 |
| **pnpm** | ≥8 | 前端包管理 | `npm i -g pnpm` |
| Docker（可选） | — | `make demo` 一键全栈 | 用方式 A 本地跑即可 |
| MinerU（可选） | 2.x | PDF 解析增强 | 无则自动 PyMuPDF 兜底 |

## 1. 首次安装（一条命令）

```bash
make install        # = cd api && uv sync  +  cd web && pnpm install
```

## 2. 配置 `.env`

```bash
cp .env.example .env
```

- 填入 LLM/Embedding 的 key（**密钥绝不入仓库**，.gitignore 已拦截）；
- **key 可以留空**：系统走抽取式降级闭环（检索/解析/阅读不受影响，回答降级为抽取式并如实标注）——这是刻意设计的离线可演示能力；
- Embedding 三选一：方舟订阅面 / 任意 OpenAI 兼容端点 / `EMBEDDING_BACKEND=local`（fastembed 本地 BGE-M3）。

## 3. 三种跑法

### 方式 A：本地开发（改代码热重载，日常推荐）

```bash
make api     # 后端 uvicorn :8100（--reload）
make web     # 前端 dev :3005（3000 留给 docker demo）
```

- 健康检查：`GET http://localhost:8100/api/health`
- 打开：`http://localhost:3005`
- 页面：`/` 文献库 · `/chat` 溯源问答 · `/reader/{id}` DocIR 阅读器 · `/audit` 透明度中心 · `/discover` `/ideas` `/graph` `/copilot` `/diff` `/memory` `/health` `/judge`

### 方式 B：演示全栈（Docker Compose，比赛现场用）

```bash
make demo    # 首次会恢复 data-real 演示快照 → docker compose up --build -d
```

- 访问：`http://localhost:3000`（API `http://localhost:8100/api/health`）
- 容器内 `MINERU_ENABLED=off`（解析走 PyMuPDF/VLM 兜底通道）；数据落宿主 `./data`
- 端口可调：`.env` 里 `API_HOST_PORT` / `WEB_HOST_PORT`

### 方式 C：只跑某个脚本 / 官方用例验收

```bash
make cases   # 官方 3 用例断言式验收（进程内，无需起服务）
make smoke   # 真 HTTP 冒烟（先 make api 或 compose 起栈）
```

## 4. 自动验证（单元测试 / 门禁）

| 命令 | 内容 | 耗时参考 |
|---|---|---|
| **`make verify`** | **一键门禁**：后端 ruff + pytest 全量 + 前端 tsc | ≈4 min |
| `powershell -File scripts/verify.ps1 -Full` | 门禁 + 前端生产构建 | ≈6 min |
| `scripts/verify.ps1 -SkipFrontend` / `-SkipBackend` | 只跑一侧 | — |
| `bash scripts/verify.sh` | Linux/macOS/CI 等价门禁（`--full` 加构建） | ≈4 min |
| `make test` | 全量门禁（ruff+pytest+tsc+build） | ≈6 min |
| `make lint` | 仅静态检查（ruff + tsc + eslint） | ≈1 min |
| `make e2e` | Playwright UI 验收（自起 api:8100 + web:3000） | ≈5 min |

- 后端测试目前 **509 passed**（含健康报告口径、去重、溯源校验、记忆子系统等回归）；
- 任一步失败 `make verify` 退出码非 0，可直接接 CI。

## 5. 数据管理

```bash
make corpus  # 对比语料收录（BERT/PreLN/GPT-2 下载→入库→解析）+ data-real 快照固化
make clean   # 清理本地运行数据（保留 data-real 快照）+ docker compose down -v
```

## 6. 常见问题排查

| 症状 | 原因 / 处理 |
|---|---|
| `uv: command not found` | 先 `pip install uv`（或按 [uv 官方文档](https://docs.astral.sh/uv/) 安装） |
| 前端 3005 被占 | `cd web && pnpm dev -- -p 3006`；或释放端口 |
| 8100 被占 | compose 的 `API_HOST_PORT` 或 `uvicorn --port` 换端口；前端 `NEXT_PUBLIC_API_BASE` 同步改 |
| 回答「未验证/拒答」多 | 多半没配 LLM key——填 `.env` 后重启 `make api`；离线演示口径见 README「诚实边界」 |
| 中文检索召回差 | Dense 未启用（BM25 对纯中文查询零召回）；配 Embedding 或 `EMBEDDING_BACKEND=local` |
| Windows 下 FTS5 报 `unable to open database file` | bash 启动环境泄漏 `TMPDIR=/tmp` 所致（db.py 已用内存临时存储根治；若复现请清空该环境变量） |
| `make demo` 起不来 | 先 `docker compose down -v` 再重试；查看 `docker compose logs api` |
| pytest 首次很慢 | fastembed/embedding 模型冷加载属正常；二次运行即快 |

## 7. 目录速览

```
scholar-agent/
├─ api/                # FastAPI 后端
│  ├─ app/             #   main.py 入口；api_routes/ 路由层；
│  │                   #   agents/ LangGraph 状态机 · rag/ 检索溯源 · parsing/ 解析管线
│  │                   #   memory/ 记忆子系统 · llm/ 客户端 · export/ PDF 导出
│  ├─ app/api_routes/health_report.py  # 结果健康评分卡（聚合实现，routes.py 留薄端点）
│  ├─ tests/           #   509+ 单元/回归测试（pytest）
│  └─ scripts/         #   官方用例验收 / 冒烟 / 评测脚本
├─ web/                # Next.js 前端（app/ 路由 + components/ + lib/）
├─ docs/               # 技术文档 · 验收快照（acceptance/）· 如何运行.md · 架构图.md
├─ data-real/          # 演示数据快照（make demo 自动恢复）
├─ scripts/            # verify.ps1 / verify.sh 一键验证门禁 · 皮肤对比度审计
├─ Makefile            # 全部入口（install/api/web/demo/test/verify/cases/smoke/e2e/clean）
└─ docker-compose.yml  # api + web 两服务单机栈
```

> 更多细节：API 全览见 `docs/api.md`；架构图见 `docs/架构图.md`；模块设计见仓库根 `docs/01~06` 方案文档。
